# 재정돋보기

**이지톤 · AI를 활용한 사회문제 해결 · 5인 팀 · 대회일 2026-11-14 · 하루 개발 프로젝트**

> 공개된 공공기관 구매 데이터를 시민이 이해하고 검증할 수 있는 정보로 바꿉니다.
> 같은 물품의 가격 차이와 그 근거를 보여주며, 낭비나 부패 여부를 단정하지 않습니다.

이 저장소는 나라장터 물품 구매 자료를 바탕으로 **기관별 구매 내역 조회 → 가격 비교 → AI 설명 → 원본 근거 확인**을 제공할 웹 서비스를 준비하는 공간입니다.

**현재는 계약 v1, 실제 연간 구매 47,795건의 검색·조회 서버와 B의 가격 비교 함수가 준비된 상태입니다.** [분석 모듈](src/budget_transparency/analysis/README.md)은 서버에 연결했고 합성 예제로 검증했습니다. 실제 비교 정책을 등록해야 실행됩니다. 실제 자료는 상태·비용 조건이 미확인이고 실제 비교 정책도 미등록입니다. React 화면은 추가됐지만 실제 브라우저 검수와 상세 화면의 Gemini 호출은 키 없이 기본 안내로 동작하며 실제 모델 호출은 아직 확인되지 않았습니다. 역할별 담당자는 아래 표와 같습니다. 서비스 이름은 재정돋보기입니다.

## 팀 작업의 필수 규칙

**파일을 수정하기 전에 반드시 자기 작업 브랜치를 만듭니다.** 코드·데이터뿐 아니라 문서·설정도 동일합니다. main 직접 작업·커밋·푸시는 금지하고, PR → 작성자 외 승인 최소 1개 → 필수 CI 통과 → Squash merge 순서로 반영합니다. 최초 저장소 초기화는 사용자가 별도로 진행합니다. 구체적인 시작 절차는 [협업 규칙](CONTRIBUTING.md)을 따릅니다.

## 1. 처음 참여한 팀원이 읽는 순서

1. 이 README에서 무엇을 만들지 확인합니다.
2. [완성 화면 명세](docs/screen-spec.md)에서 카드 목록과 상세 패널의 모습을 확인합니다.
3. [역할 안내](docs/roles/README.md)에서 자신의 역할을 찾고, 해당 문서의 작업 순서를 따릅니다.
4. [협업 규칙](CONTRIBUTING.md)과 [금지 사항](docs/RULES-DO-NOT.md)을 읽습니다.
5. E에게 실행 환경과 공통 예제를 받아 자신의 작업을 시작합니다.

개발 경험이 없어도 각 역할 문서에서 **만들 파일, 넣을 내용, 작업 순서, 전달할 결과, 완료 확인 방법**을 찾을 수 있습니다. 시간표보다 실행 가능한 결과를 기준으로 진행합니다.

## 2. 왜 만드는가

공공계약 정보는 공개되어 있지만 자료의 양과 구조 때문에 시민이 직접 비교하기 어렵습니다. 기관별 구매 내역을 나열하는 것만으로는 어떤 가격을 왜 비교해야 하는지 알기 어렵습니다.

우리 서비스는 같은 제품의 구매 가격을 비교하고, 시민이 다음 질문에 답을 찾도록 돕습니다.

- 어떤 기관이 어떤 물품을 얼마에 구매했는가?
- 같은 물품을 구매한 다른 기관과 단가가 얼마나 다른가?
- 확인된 시중 가격이 있다면 구매 단가와 얼마나 다른가?
- 비교 대상과 계산 기준은 무엇이며, 어떤 조건은 확인하지 못했는가?
- 원본 공공데이터에서 이 내용을 직접 확인할 수 있는가?

**핵심 가치는 시민 접근성, 일관된 비교 기준, 확인 가능한 근거입니다.** 가격이 다르다는 사실만으로 잘못된 계약이라고 결론내리지 않습니다.

## 3. 최종적으로 만들 화면

사용자가 제공한 참고 사진처럼 **흰 배경, 둥근 카드 목록, 주황색 가격 비교 막대, 오른쪽 상세 패널**을 만듭니다. 구체적인 배치와 동작은 [화면 명세](docs/screen-spec.md)를 따릅니다.

### 목록 화면

| 영역 | 표시할 내용 | 사용자가 하는 행동 |
|---|---|---|
| 상단 안내 | 서비스 설명, 데이터 기준일·범위 | 어떤 자료를 보는지 확인 |
| 검색창 | 기관이나 물품을 입력하는 칸 | 검색 버튼 또는 Enter |
| 필터 | 기관, 품목, 비교 유형, 비교 상태 | 보고 싶은 자료 선택 |
| 결과·정렬 | 검색 결과 수, 구매일·차이율 정렬 | 같은 기준의 자료 비교 |
| 구매 카드 | 기관·품목·구매일·단가·차이·상태 | 자세히 보기 클릭 |

카드에는 구매 단가와 비교 기준을 두 막대로 보여줍니다. 기관 간 비교의 기준은 다른 기관의 비교 가능한 구매 자료이며, 시중가 비교의 기준은 별도로 확인한 판매 가격입니다. 두 기준을 혼용하지 않습니다.

### 오른쪽 상세 패널

카드를 누르면 배경이 어두워지고 오른쪽에 상세 패널이 열립니다. 모바일에서는 전체 폭으로 표시합니다.

- 품목명, 모델·규격, 기관명, 구매일과 계약 식별자
- 구매 단가, 비교 기준 단가, 차액과 차이율
- 비교에 사용한 다른 구매 기록 또는 시중가 근거
- 수량 단위, 부가세·배송·설치 비용의 확인 여부
- 계산식, 비교 대상 수·기간, 제외한 기록과 이유
- AI 설명과 추가로 확인할 사항
- 원본 출처, 수집일, 원본 열기 버튼

자료가 부족하면 “자료 부족”, 조건이 불명확하면 “조건 확인 필요”를 표시합니다. 계산하지 못한 값을 0원으로 표시하지 않습니다. 참고 사진의 “예상 절감액” 대신 **“비교 기준 대비 단가 차이”**를 사용합니다.

## 4. 기능 범위와 완성 우선순위

먼저 물품 한 종류에서 검색부터 근거 확인까지 연결합니다. 그다음 검증된 물품을 추가합니다.

| 구분 | 만들 기능 | 완료 모습 |
|---|---|---|
| 핵심 | 기관·물품 검색과 구매 목록 | 조건을 바꾸면 실제 카드 목록이 바뀜 |
| 핵심 | 기관 간 동일 물품 단가 비교 | 비교 대상·기준·차이·한계를 확인 가능 |
| 핵심 | 카드와 상세 근거 패널 | 목록의 숫자를 상세와 원본에서 확인 가능 |
| AI 목표 | 계산 결과에 근거한 쉬운 설명 | 근거 없는 원인 추정 없이 설명 제공 |
| AI 목표 | 자연어 검색 조건 추출 | 문장을 기관·품목·기간으로 해석하고 표시 |
| 데이터 확보 시 추가 | 시중가와 구매 단가 비교 | 같은 제품의 확인된 가격·조건·출처 제공 |

시중가가 없으면 해당 영역에 자료가 없음을 표시합니다. 자연어 검색이나 AI 설명이 실패해도 일반 검색·필터·계산 결과·출처 열람은 유지합니다. 일정상 AI 기능을 줄여야 한다면 근거 기반 설명부터 완성하고 자연어 검색을 이어 붙입니다. AI 미연결 상태를 연결된 것으로 발표하지 않습니다.

회원가입, 지도, 전국 실시간 수집, 기관 청렴도 순위, 수의계약 집중 분석, 계약 변경 패턴 분석은 당일 구현 범위에서 제외합니다. 동일 품목 내 가격 차이 정렬은 가능하지만 기관 전체의 부패·낭비 순위로 부르지 않습니다.

## 5. 데이터와 AI가 각각 하는 일

```text
공식 자료 다운로드
    ↓
출처·필드 의미 확인 → 정규화 JSON 저장
    ↓
검색·필터 → Python으로 비교 대상 선택 및 가격 차이 계산
    ↓
계산 결과 + 원본 근거 + 확인하지 못한 조건
    ├─ 웹 화면의 숫자·차트·출처로 직접 표시
    └─ Gemini가 시민이 이해하기 쉬운 문장으로 설명
```

자연어 검색을 사용하면 Gemini가 먼저 질문을 검색 조건으로 바꿉니다. 실제 검색은 서버가 저장된 데이터에서 수행합니다.

| 작업 | 맡는 부분 |
|---|---|
| 실제 가격과 계약 근거 제공 | 확인한 공개 데이터 |
| 동일 제품·비교 조건 확인 | 식별번호·규격·단위 규칙과 데이터 검수 |
| 차액·차이율·정렬 | Python 코드 |
| 질문 해석·분류 보조·설명 | Gemini API |
| 숫자·출처의 일치 확인 | 코드 검증과 원본 대조 |
| 화면 표시 | 웹 앱 |

**AI 모델을 직접 학습시키지 않습니다. GPU도 필요 없습니다.** Gemini는 원격 API를 사용하고 팀원 노트북에서는 데이터 처리·서버·화면을 개발합니다. 모델 ID와 사용 가능 한도는 실제 계정에서 확인한 뒤 설정합니다.

같은 AI에게 반복해서 질문하는 것을 독립적인 교차 검증이라고 부르지 않습니다. 신뢰성은 실제 원본, 코드 계산, 제품·조건 확인, AI 응답 검증으로 확보합니다. LLM이 가격이나 출처를 만들어 빈 자료를 채우게 하지 않습니다.

## 6. 어떤 데이터를 준비하는가

첫 버전은 공공데이터포털에서 내려받은 자료를 JSON으로 정리해 사용합니다. 매번 공공 API를 실시간 호출할 필요는 없습니다. 정확한 데이터셋·필드·이용 조건은 아직 확인해야 합니다.

| 준비할 정보 | 필요한 이유 |
|---|---|
| 물품 식별번호·모델·규격·품목명 | 같은 제품인지 확인하고 화면에 표시 |
| 구매 기관 식별자·이름 | 기관별 검색과 비교 |
| 구매일·대상 기간 | 시점이 다른 가격을 무조건 비교하지 않기 위해 |
| 수량·단위·단가·가격의 의미 | 개당 가격과 총계약금액 구별 |
| 계약 식별자·변경·취소 상태 | 중복 집계와 취소 기록 제외 |
| 부가세·배송·설치 포함 여부 | 가격 조건 확인 |
| 출처·원본 ID·수집일 | 원본 추적과 기준일 안내 |

내부 필드 이름과 뜻은 [데이터 계약 초안](docs/contracts/data-model.md)에 있습니다. 모르는 값은 `null`로 두며, 원본에 없는 항목을 추정하여 채우지 않습니다.

시중가는 별도 자료입니다. 같은 모델의 가격, 판매처, 확인 날짜, 출처 URL, 수량 단위와 포함 비용을 기록해야 합니다. 구매 자료만으로 시중가를 알 수는 없습니다.

**가장 먼저 할 일은 큰 데이터를 모으는 것이 아니라, 같은 제품의 여러 기관 구매 기록 몇 건이 실제로 비교 가능한지 확인하는 것입니다.** A가 전체 자료를 정리하는 동안 나머지 팀원은 공통 합성 예제로 개발합니다. 합성 자료에는 예시 표시를 붙이고 실제 분석 결과와 구분합니다.

상세 절차: [데이터 확보 안내](docs/data-sources.md) · [데이터 폴더 안내](data/README.md) · [출처 등록 양식](data/sources/README.md)

## 7. 가격 비교를 이해하는 예시

다음은 **화면과 계산을 확인하기 위한 합성 예시**이며 실제 공공기관 자료가 아닙니다. 같은 제품과 비교 가능한 조건을 가정합니다.

| 구매 기관 | 단가 |
|---|---:|
| 예시기관 A — 분석 대상 | 150,000원 |
| 예시기관 B | 100,000원 |
| 예시기관 C | 120,000원 |
| 예시기관 D | 140,000원 |

다른 기관 세 구매의 중앙값은 120,000원입니다.

```text
차액 = 150,000 - 120,000 = 30,000원
차이율 = 30,000 / 120,000 × 100 = 25%
```

카드와 상세 패널에는 `+30,000원 (+25%)`와 세 비교 기록을 함께 표시합니다. 이것은 30,000원을 낭비했다는 판정이 아닙니다.

실제 적용할 비교 기간·최소 표본·조건·집계 방식은 데이터 확인 후 [결정 기록](docs/decisions.md)에 명시합니다. 기준값이 없거나 0이면 차이율을 계산하지 않습니다. 비교 표본이나 조건이 불충분하면 판단을 유보합니다.

## 8. 5명이 무엇을 만드는가

담당자는 아래와 같습니다. 각자 결과물을 만들고 검증하며, E 최진필이 환경 설정과 통합을 담당합니다. GitHub 계정과 CODEOWNERS는 계정 확인 후 반영합니다.

| 역할 | 담당자 | 직접 만들 결과 | 전달받는 것 | 넘길 대상 |
|---|---|---|---|---|
| [A · 데이터](docs/roles/A-data.md) | 김종현 | 구매 JSON, 시중가 자료, 출처·원본 대조 기록 | E의 공통 데이터 예제 | B·E에 데이터, D에 출처 검토 |
| [B · 비교·계산](docs/roles/B-analysis.md) | 이선념 | 가격 비교 함수, 계산 테스트, 수치 검수 기록 | A의 데이터, E의 응답 형식 | E에 함수, C·D에 숫자의 의미 |
| [C · AI](docs/roles/C-ai.md) | 김성현 | 자연어 조건 추출, 근거 설명, 오류 대체 문장 | B의 근거 묶음, E의 API 환경 | E에 함수, D에 설명 상태 |
| [D · 웹 화면](docs/roles/D-web.md) | 박정호 | 검색·필터, 카드, 가격 막대, 상세 패널 | E의 화면 응답 예제·조회 함수 | E에 화면, 전원에 검수 화면 |
| [E · 환경·통합](docs/roles/E-integration.md) | 최진필 | 실행 환경, 공통 예제, 서버 API, 모듈 연결 | A~D의 파일과 호출 예제 | 전원에 실행 방법과 연결 결과 |

A는 발표 근거, B는 시연 수치, C는 AI 동작과 한계, D는 화면 녹화, E는 실행·제출 확인을 맡습니다. 발표자는 별도로 정합니다. E가 모든 사람의 코드와 검증을 대신하지 않습니다.

## 9. 실제 작업 순서

1. **E가 기본 환경과 공통 예제를 만듭니다.** 팀원 모두 빈 화면 또는 자기 예제를 실행할 수 있어야 합니다.
2. **A·B가 실제 표본을 확인합니다.** 가격과 물품의 의미가 비교 가능한지 판단합니다.
3. **B·C·D가 같은 예제로 작업합니다.** 계산 함수, 기본 설명, 카드·패널을 각각 만듭니다.
4. **E가 실제 데이터를 연결합니다.** 검색부터 비교와 근거 화면까지 한 물품으로 완성합니다.
5. **C·E·D가 AI를 연결합니다.** 생성 설명이 실패해도 이미 계산한 결과는 유지합니다.
6. **근거가 확보되면 시중가 비교를 연결합니다.** 자료가 없으면 없음 상태를 보여줍니다.
7. **전원이 화면과 원본을 대조합니다.** 오류·자료 부족·좁은 화면도 확인합니다.
8. **발표·녹화·실행 안내를 완성합니다.** 실제 구현 범위와 한계를 정확히 전달합니다.

상세 기준은 [작업 순서](docs/roadmap.md)에 있습니다. 각자가 완성한 뒤 마지막에 한꺼번에 합치지 않고, 작은 기능부터 연결합니다.

### 작업을 팀원에게 넘길 때

```text
완료한 것:
파일 경로:
입력 예시:
실제로 확인한 결과:
받아서 사용할 사람:
남은 문제 또는 필요한 도움:
```

“코드를 만들었다”만으로 완료 처리하지 않습니다. 화면을 직접 열거나 예제로 함수를 실행한 결과를 함께 공유합니다. 키나 키가 포함된 URL은 첨부하지 않습니다.

## 11. 개발 환경과 실행 안내

D의 React 화면이 추가됐습니다. 서버를 별도 터미널에서 먼저 실행한 뒤, 다른 터미널에서 `npm ci --prefix apps/web`과 `npm run dev --prefix apps/web`을 실행하고 표시된 주소를 엽니다. 현재 구매 카드 기본 모드는 실제 연간 데이터이며 비교 함수는 실제 정책 등록 후 동작합니다. 도청 순위·점수는 구현되지 않았고 Gemini 실제 호출은 미검증입니다. 자세한 내용은 [웹 실행 안내](apps/web/README.md)를 확인합니다.


현재 FastAPI 서버는 실제 연간 구매 데이터 47,795건의 목록·상세·검색·필터를 제공합니다. B의 비교 함수는 서버에 연결됐으며 실제 비교 정책이 등록되면 동작합니다. 상세 화면은 AI 설명을 별도로 요청하며, 키가 없으면 기본 안내를 표시합니다. 실제 Gemini 호출은 아직 검증하지 않았습니다. B 테스트는 개발 의존성 설치 후 `python3 -m unittest discover -s tests/unit -p test_compare.py -v`로 실행합니다.

| 영역 | 현재 후보·방향 |
|---|---|
| 웹 화면 | React/TypeScript 후보 |
| 서버·계산 | Python/FastAPI 후보 |
| 저장 | 초기 JSON 파일 |
| AI | Gemini API, 모델 ID·사용 조건은 연결 전 확인 |

### 구매 조회 서버 실행 (macOS)

저장소 최상위 폴더에서 다음 명령을 순서대로 실행합니다. Python 3.12 이상이 필요합니다. 첫 설치에는 인터넷이 필요합니다.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-server.txt -r requirements-dev.txt
.venv/bin/python -m uvicorn budget_transparency.api.server:app --app-dir src --host 127.0.0.1 --port 8000 --reload
```

터미널을 켜 둔 상태에서 브라우저로 다음 주소를 엽니다.

- [구매 목록](http://127.0.0.1:8000/api/purchases): 실제 연간 구매 자료 47,795건
- [기관·물품 선택지](http://127.0.0.1:8000/api/options): 자료에 있는 기관·물품
- [API 사용 화면](http://127.0.0.1:8000/docs): FastAPI가 제공하는 호출 확인 화면. 화면 리소스를 불러오려면 인터넷이 필요할 수 있습니다.

JSON에 `synthetic: false`가 표시되는 실제 구매 자료입니다. 비교 함수는 연결됐지만 실제 정책이 등록되지 않아 현재 결과는 `unavailable`, 차액은 `null`입니다. 상세 AI 설명은 키가 없으면 기본 안내이며 자연어 검색은 아직 서버에 연결되지 않았습니다. 서버 종료는 터미널에서 Ctrl+C를 누릅니다. Windows 실행 방법은 [서버 안내](src/budget_transparency/api/README.md)를 봅니다.

### 로컬 설정 양식

macOS/Linux에서는 저장소 루트에서 다음 명령으로 양식을 복사할 수 있습니다. 기존 `.env`가 있으면 덮어쓰지 않고 내용을 확인합니다.

```bash
cp -n .env.example .env
```

Windows에서는 파일 탐색기나 편집기로 `.env.example`을 복사해 `.env`로 만들 수 있습니다.

- `GEMINI_API_KEY`: AI 호출용 키. 실제 값은 로컬 `.env`에만 둡니다.
- `GEMINI_MODEL`: 실제로 사용 가능한지 확인한 모델 ID.
- `DATA_GO_KR_SERVICE_KEY`: 공공 API 수집을 구현할 때만 사용. 파일 다운로드 방식에는 필요하지 않습니다.

환경 변수 양식이 있다고 연결 기능이 구현된 것은 아닙니다. 서버가 `.env`를 읽는 방식은 E가 구현합니다. 비밀 키를 프런트 코드·JSON·GitHub·로그에 넣지 않습니다.

### 지금 실행할 수 있는 문서 검사

```bash
python3 scripts/check_docs.py
git diff --check
```

첫 명령은 문서의 상대 파일 링크를 확인합니다. 두 번째는 Git 변경의 공백 오류를 확인합니다. 이것은 서비스 기능 테스트를 대신하지 않습니다.

## 12. 완성했다고 판단하는 기준

### 데이터와 수치

- [ ] 실제 시연 구매 기록의 제품·기관·단가를 원본과 대조했다.
- [ ] 중복·취소·변경 기록과 결측을 처리하고 이유를 기록했다.
- [ ] 비교 조건·기준 단가·표본 수·계산 결과를 확인할 수 있다.
- [ ] 합성 예제의 30,000원·25%와 예외 사례가 테스트를 통과한다.
- [ ] 시중가가 없거나 조건이 불명확할 때 결과를 만들어내지 않는다.

### 화면과 AI

- [ ] 참고 사진처럼 카드 목록·가격 막대·오른쪽 상세 패널이 있다.
- [ ] 검색·필터를 바꾸면 실제로 결과가 달라진다.
- [ ] 카드마다 올바른 상세가 열리고 카드·상세의 수치가 같다.
- [ ] 비교 근거와 원본 출처를 확인할 수 있다.
- [ ] AI가 존재하지 않는 숫자·출처·차이의 원인을 추가하지 않는다.
- [ ] AI 오류에도 일반 검색·수치·근거 열람이 유지된다.
- [ ] 자료 부족·조건 불명·검색 결과 없음·서버 오류를 구분한다.
- [ ] 작은 화면에서도 금액과 출처, 닫기 버튼을 사용할 수 있다.

### 실행과 제출

- [ ] 다른 팀원이 README의 실행 안내를 따라 서비스를 켤 수 있다.
- [ ] 시연 영상 또는 화면 녹화를 준비했다.
- [ ] 발표에 데이터 기준일·범위·한계와 실제 AI 구현 여부를 표시했다.
- [ ] 대회가 요구하는 제출 형식·배포 여부를 확인했다.

검증 절차: [테스트 계획](docs/testing.md) · [시연 시나리오](docs/demo-scenario.md)
