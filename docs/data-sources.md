# A가 따라 하는 데이터 준비 절차

담당 A, 가격 의미 검토 B, 변환·로딩 지원 E. 실제 사용할 공식 데이터셋·필드는 아직 확인되지 않았습니다.

## 1. 자료를 고르기

나라장터 물품 계약·쇼핑몰 품목·납품요구 자료 등을 후보로 확인합니다. 다운로드 파일을 먼저 사용할 수 있습니다. 대화에 등장한 용역계약 임시 API 주소는 검증되지 않았고 물품 자료로 채택하지 않습니다.

물품 식별번호·모델·규격, 기관, 구매일, 수량·단위, 구매 단가를 확인할 수 있는 작은 표본을 B에게 전달합니다. “금액” 열이 무엇을 뜻하는지 공식 설명도 가져옵니다. 비교 가능한 자료인지 확인하기 전에 전체 수집을 시작하지 않습니다.

## 2. 출처 문서 만들기

`data/sources/purchases.md`에 제공기관·자료명·공식 링크·수집일·대상 기간·이용 조건·원본 파일명과 식별자를 기록합니다. 각 원본 열을 [내부 필드](contracts/data-model.md)에 어떻게 옮겼는지 대응표를 작성합니다. 인증키가 붙은 URL은 쓰지 않습니다.

## 3. JSON으로 정리하기

원본은 `data/raw/`, 작업 결과는 `data/processed/`에서 관리합니다. 공유 가능한 작은 검수 자료만 `data/demo/purchases.json`에 넣습니다. 원본과 작업 데이터는 기본 Git 제외입니다.

E가 준 공통 형식에 맞춰 값들을 옮깁니다. null은 모름, 0은 실제 0이므로 바꿔 쓰지 않습니다. 부가세·배송·설치 포함 여부는 true/false/null로 기록합니다. 같은 계약의 수정·취소를 독립 구매처럼 중복 집계하지 않습니다. 원본에 없는 가격을 생성하지 않습니다.

파일을 만든 뒤 `python3 -m json.tool data/demo/purchases.json`으로 문법을 확인합니다. Windows의 Python 명령은 E에게 확인합니다. 문법 통과 뒤에도 시연 자료의 가격·수량·기관을 원본과 사람이 대조해야 합니다.

## 4. 시중가를 별도로 기록하기

`data/demo/market-prices.json`에 동일 제품의 판매처·가격·단위·확인일·URL·포함 조건을 기록합니다. 없으면 빈 배열 `[]`로 전달합니다. 검색 요약의 숫자만 가져오거나 같은 이름의 다른 규격을 사용하지 않습니다. 등록된 상품 가격과 실제 구매 단가도 구별합니다.

## 5. 전달물과 완료 조건

A는 두 JSON, 출처 문서, `docs/evidence/data-check.md`를 B·E에게 넘깁니다. 검증 기록에는 확인한 행·원본 위치·결측·제외 사유를 적습니다. D가 표시한 실제 카드도 다시 대조합니다.

- [ ] 제품·기관·단가의 의미를 설명할 수 있다.
- [ ] 원본까지 찾아갈 수 있다.
- [ ] 이용 조건과 불필요한 개인정보를 확인했다.
- [ ] 변경·취소·중복과 모르는 조건을 처리했다.
- [ ] B가 계산에 사용할 수 있는지 확인했다.

## API 자동 수집을 추가할 경우

E와 공식 명세의 주소·필수 조건·인증·페이지 처리를 확인합니다. timeout, 호출 제한·재시도, HTTP 상태와 응답 본문 오류를 모두 처리합니다. API 키나 전체 인증 URL을 로그에 출력하지 않습니다. 자동 수집은 초기 필수 기능이 아닙니다.
