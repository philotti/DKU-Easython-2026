# B · 카드에 표시할 가격 차이 계산하기

담당자: 이선념(B). 목표는 입력 JSON을 받아 카드와 상세 화면의 숫자를 반환하는 함수 하나를 만드는 것입니다. 모델 학습은 하지 않습니다.

## 만들어서 전달할 것

| 만들 파일 | 넣을 내용 |
|---|---|
| `src/budget_transparency/analysis/compare.py` | 비교군 선택·가격 차이 계산 |
| `tests/unit/test_compare.py` | 손계산 예제와 예외 검증 |
| `docs/evidence/calculation-check.md` | 실제 시연 수치 대조 결과 |

## 작업 순서

### 1. 계산할 입력을 확인하기

A의 자료와 E의 공통 예제를 받습니다. 단가·수량 단위·제품 식별자·기관·날짜를 읽는 방법을 E에게 확인합니다. 혼합 품목 계약 총액을 임의로 나눠 단가를 만들지 않습니다.

읽는 형식은 [데이터 계약 v1](../contracts/data-model.md), 포함·제외와 상태는 [비교 규칙 v1](../contracts/comparison-policy.md)을 따릅니다. 공통 합성 입력은 `tests/fixtures/contracts-v1/`에 있습니다. 금액·수량은 십진 문자열을 Decimal로 읽고, 날짜는 YYYY-MM-DD로 읽습니다. 조건의 null은 같거나 0인 값으로 취급하지 않습니다.

2026-11-14 확인 결과와 재검사 명령은 [B 입력 확인 기록](../evidence/calculation-check.md)에 있습니다.

- [x] E의 공통 합성 구매·시중가·정책과 응답 예제를 확인하고 계약 검사를 실행했다.
- [x] 단가·수량·단위·물품 식별자·기관·날짜의 필드와 타입을 확인했다.
- [x] A의 PR #3 시연 18행을 확인했다. 현재 B 브랜치에는 PR #3이 반영되어 있으며 로컬 구매·시중가 JSON 2개의 검사를 통과했다.
- [x] 실제 입력의 unknown/null/빈 시중가 및 동일 수량 표본 한계를 확인했다.
- [ ] A·E와 실제 상태 매핑, 비용 조건, 기관 코드 대응 및 실제 분석 정책을 확정한다.
- [ ] E와 정책·데이터 버전 초기화 및 정책 미등록 응답 표현을 확인한다.

입력 형식 검토는 완료하여 합성 예제로 2번 함수 구현을 시작할 수 있습니다. 실제 데이터의 계산 준비와 A·E의 추가 합의는 미완료입니다. 문서·서버 코드 검토를 E의 별도 확인 답변이나 실제 계산 실행으로 간주하지 않습니다.

### 2. 함수 만들기

`compare_purchase(record_id, purchases, market_prices, comparison_type)`을 구현합니다. comparison_type은 `agency`(기관 간), `market`(시중가)로 나눕니다. 파일 로딩·서버·Gemini 호출은 E·C가 맡으므로 이 함수에 넣지 않습니다.

`src/budget_transparency/analysis/compare.py`와 `tests/unit/test_compare.py`를 추가했습니다. agency/market 비교와 상태·근거 반환을 구현하고 합성 정책으로 검증했습니다. E는 `configure_analysis(policy, dataset_version)` 또는 데이터셋별 `ComparisonEngine`으로 초기화할 수 있습니다. 호출 방법과 예외는 [분석 모듈 안내](../../src/budget_transparency/analysis/README.md)를 따릅니다. 이 초기화 API는 B가 제공하는 연결 지점이며 E 서버에 반영됐다는 뜻은 아닙니다. 실제 정책이나 미등록 정책의 응답 표현은 아직 확정하지 않았습니다.

### 3. 기관 간 비교 구현하기

대상과 같은 제품·규격·단위이고 확인된 조건이 호환되는 자료를 고릅니다. 대상 기관의 구매와 중복 기록은 제외합니다. 비교 기간·최소 표본 기준은 실제 표본을 보고 E·A와 결정하여 계약에 기록합니다. 아직 결정하지 못했으면 자료 나열까지만 하고 비교 가능으로 판정하지 않습니다.

비교 가능한 구매 건들의 중앙값을 구합니다. `차액 = 구매 단가 - 중앙값`, `차이율 = 차액 / 중앙값 × 100`입니다. 양수는 기준보다 비쌈, 음수는 저렴함입니다. 기준값이 0·null이면 차이율은 null입니다. 중앙값은 금액순으로 정렬했을 때 가운데 값이며 짝수이면 가운데 둘의 평균입니다.

### 4. 시중가 비교 구현하기

A가 확인한 동일 제품·호환 조건의 가격만 씁니다. 여러 판매가가 있으면 채택 기준을 E·A와 명시합니다. 임의로 가장 싼 가격을 선택하지 않습니다. 시중가가 없으면 `insufficient_data`와 이유를 반환합니다. 기관 간 중앙값으로 대신 채우지 않습니다.

### 5. 응답 만들기

대상 ID, 비교 유형, 상태, 구매 단가, 기준 단가, 차액, 차이율, 비교 기록 목록, 제외 사유, 표본 수·기관 수, 한계, 출처 ID를 반환합니다. 정확한 필드 이름은 E의 공통 예제와 맞춥니다. 원본 숫자는 유지하고 화면 반올림 규칙을 D에게 전달합니다.

### 6. 정답을 아는 예제로 확인하기

[화면 명세](../screen-spec.md)의 150,000원 대 100,000·120,000·140,000원 예제에서 기준 120,000원, 차액 30,000원, 차이율 25%인지 검사합니다. 다른 규격 제외, 대상 기관 제외, 중복 제외, 빈 비교군, 0원 기준, 음수 차이도 테스트합니다. 테스트 실행 명령은 E가 환경을 만든 뒤 확인해 문서에 기록합니다.

### 7. 실제 자료 대조하기

A와 시연 카드의 수치를 직접 계산해 일치하는지 확인합니다. 함수·테스트를 E에게, 화면 숫자의 의미를 C·D에게 넘깁니다. “통계적 이상치”나 기관 청렴도 점수는 만들지 않습니다.

## 완료 확인

- [x] 자료가 없을 때 null과 이유가 반환된다(등록된 정책 기준).
- [x] 비교에 쓴 원본 기록 목록을 반환한다.
- [ ] 카드와 패널에서 같은 결과를 쓴다.
