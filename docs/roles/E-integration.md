# E · 초보 팀원이 작업할 환경과 연결 만들기

담당자: 미정. 개발 경험이 있는 사용자에게 추천하는 역할입니다. 다른 네 사람의 일을 모두 대신하기보다 공통 예제·실행 환경·연결 지점을 먼저 제공하는 역할입니다.

## 만들어서 전달할 것

| 만들 파일 | 넣을 내용 |
|---|---|
| `src/budget_transparency/api/server.py` | 서버 시작과 API 경로 |
| `src/budget_transparency/search/repository.py` | JSON 읽기·검색·필터 |
| `apps/web/src/api.ts` | 화면이 서버를 호출하는 함수 (React 제안) |
| `tests/fixtures/purchases.synthetic.json` | 공통 합성 구매 예제 |

| 프로젝트 설정 파일 | 실제 선택한 의존성과 실행 명령 |
| `tests/integration/test_flow.py` | 검색→비교→상세 경로 검증 |

아래는 구현할 작업이며 파일이 이미 존재한다는 뜻은 아닙니다.

## 작업 순서

### 1. 팀원이 실행할 환경 만들기

팀이 사용할 스택을 하나 정하고 docs/plan.md에 기록합니다. Python 서버와 React 화면은 후보이며 익숙한 조합을 우선합니다. Python 버전·가상환경·의존성, 프런트 런타임·의존성, 설치·실행 명령을 README에 적습니다. 각 팀원이 빈 화면까지 실행하는 것을 확인합니다. AI는 원격 API를 쓰므로 로컬 모델·GPU 설정은 하지 않습니다.

### 2. 공통 예제와 형식 제공하기

screen-spec.md의 합성 구매 예제를 파일로 만듭니다. 같은 제품의 네 기관, 다른 규격, 자료 부족 사례를 포함합니다. `synthetic: true`를 명시하고 실제 URL을 붙이지 않습니다. A에게 정규화 예제, B에게 함수 입력, C에게 근거 묶음, D에게 카드·상세 응답 예제를 제공합니다. 초보자가 서로 다른 필드명을 만들지 않게 합니다.

### 3. API 통로 만들기

구현 경로 제안: `GET /api/purchases`는 검색·필터 목록, `GET /api/purchases/{record_id}`는 대상·비교 상세, `POST /api/query`는 자연어 검색 조건, `POST /api/purchases/{record_id}/explanation`은 설명입니다. `comparison_type`을 agency/market으로 제한합니다. 정확한 요청·응답 예제를 [공동 API 계약](../contracts/analysis-api.md)에 적습니다. 처음에는 합성 응답을 반환해 D가 붙이게 합니다.

### 4. 데이터를 읽고 비교 함수 연결하기

A의 JSON을 로딩·검사합니다. ID 중복이나 필수 필드 오류는 원인을 알려줍니다. repository.py에서 검색·필터를 적용하고 B의 compare_purchase를 호출합니다. 모르는 구매 ID는 404, 잘못된 조건은 적절한 오류로 구분합니다. 목록과 상세는 같은 계산 결과를 사용합니다.

### 5. AI 연결하기

C의 parse_query와 explain_analysis를 연결합니다. 키는 환경 변수에서만 읽고 브라우저에 전달하지 않습니다. 비교 결과를 먼저 반환하고 설명은 별도로 요청하여 느린 AI가 카드 표시를 막지 않게 합니다. timeout·오류 대체를 확인합니다.

### 6. 화면 연결하기

D에게 api.ts의 호출 방법을 제공합니다. 화면 주소와 서버 주소가 다르면 필요한 개발용 연결 설정을 적용합니다. 검색·기관 필터·품목 필터·정렬·카드 클릭·원본 열기를 함께 실행합니다. 단계마다 화면을 확인하며 마지막에 한꺼번에 합치지 않습니다.

### 7. 시연 환경 완성하기

대회가 배포를 요구하는지 확인합니다. 필수라면 초기에 최소 화면으로 배포 경로부터 확인하고, 선택이면 발표 노트북 로컬 실행을 먼저 완성합니다. 다른 팀원이 README만 보고 실행하는지 확인합니다. AI 키를 제거한 상태에서도 비교·출처 열람이 되는지 시험합니다. A는 발표 근거, B는 수치, C는 AI 결과, D는 화면·녹화를 맡습니다.

## 완료 확인

- [ ] A~D가 각자 자기 작업을 실행할 수 있다.
- [ ] 공통 예제와 실제 데이터가 구분된다.
- [ ] 검색→카드→상세→원본이 연결된다.
- [ ] 서버와 브라우저의 숫자가 일치한다.
- [ ] AI 장애가 비교 화면을 중단시키지 않는다.
- [ ] 실제 실행 명령과 검증 결과를 기록했다.

## 막혔을 때 전달할 내용

어느 단계인지, 파일 경로, 입력, 기대 결과, 실제 오류를 E와 관련 담당자에게 전달합니다. 인증키는 지웁니다. 없는 데이터나 기능을 완료된 것처럼 만들지 않습니다. [공통 역할 안내](README.md)와 [완성 화면 명세](../screen-spec.md)를 기준으로 확인합니다.
