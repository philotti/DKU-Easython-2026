# 처음 개발하는 팀원을 위한 역할 안내

시간 할당 대신 **만들 파일 → 작업 순서 → 전달물 → 확인 방법**으로 진행합니다. 하루 해커톤이며, 모델 학습과 GPU는 필요 없습니다. 아래 경로와 함수는 앞으로 만들 구현의 설계안입니다. 아직 실행되는 서비스는 없습니다.

## 먼저 볼 문서

1. [완성 화면 명세](../screen-spec.md): 사용자 참고 사진을 어떤 화면으로 만들지 확인합니다.
2. [작업 순서](../roadmap.md): 다른 사람에게 무엇을 받아야 하는지 확인합니다.
3. 자신의 역할 문서: 체크박스 순서대로 진행합니다.

| 역할 | 만들 결과 | 담당자 |
|---|---|---|
| [A 데이터](A-data.md) | 구매 JSON·시중가 근거·출처 기록 | 김종현 |
| [B 계산](B-analysis.md) | 가격 비교 함수·검증 예제 | 이선념 |
| [C AI](C-ai.md) | 검색 조건 추출·근거 설명 함수 | 김성현 |
| [D 화면](D-web.md) | 사진처럼 보이는 카드 목록·상세 패널 | 박정호 |
| [E 연결](E-integration.md) | 개발 환경·서버·모듈 연결·실행 안내 | 최진필 |

위 역할 배정은 확정입니다. GitHub 계정은 별도로 확인한 뒤 CODEOWNERS에 반영합니다. 초보자에게 서버 설정·배포를 각자 맡기지 않습니다. E가 모두 같은 예제를 사용하도록 준비하고 A~D는 자기 파일에 집중합니다.

## 용어

- JSON: 데이터를 이름과 값으로 저장한 파일. 예: `{"unit_price": 150000}`.
- 함수: 입력을 받아 결과를 돌려주는 코드 묶음.
- API: 화면이 서버에 데이터를 요청하는 통로.
- 응답 예제/픽스처: 실제 자료가 없어도 화면과 계산을 개발하는 공통 연습 자료. 합성이라고 표시합니다.
- null: 값이 0이라는 뜻이 아니라 모른다는 뜻.
- 커밋/PR: 변경 내용을 저장하고 팀원이 검토하는 방법. 처음 사용 시 E와 함께 진행합니다.

## 작업을 전달하는 방법

“완료했어요” 대신 **파일 경로 / 입력 예시 / 결과 / 확인한 방법 / 남은 문제**를 함께 보냅니다. 다른 역할의 파일을 바꿔야 하면 먼저 해당 담당자에게 알립니다. 공유 계약은 E가 정리하고 A~D가 자기 입력·출력을 확인합니다.

## AI 코딩 도구에 부탁할 때

자신의 역할 문서와 screen-spec.md를 먼저 읽게 합니다. “내 역할의 첫 번째 작업만 구현하고, 입력과 출력 예제로 확인해 줘. 공통 데이터 형식은 임의로 바꾸지 말고, 실제로 실행한 검증만 보고해 줘”처럼 작은 단위로 요청합니다. 생성된 코드가 있다는 것과 기능이 동작한다는 것은 다릅니다. 각 작업의 확인 항목을 직접 따라 합니다.
