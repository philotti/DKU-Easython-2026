# 실제 확인 결과를 남기는 곳

계획이나 “잘 됩니다”라는 소감 대신 입력과 결과를 기록합니다. 아래 파일은 담당자가 검증을 수행한 뒤 만듭니다. 빈 파일을 통과 증빙으로 사용하지 않습니다.

| 파일 | 담당 | 기록할 내용 |
|---|---|---|
| data-check.md | A | 원본·제품·기관·가격·결측·중복 대조 |
| calculation-check.md | B | 정답 예제·실제 가격 계산·비교 제외 |
| ai-check.md | C | 질문별 조건·근거 검증·장애 처리 |
| ui-check.md | D | 카드·패널·모바일·키보드·오류 상태 |
| integration-check.md | E | 실제 데이터 전체 흐름·다른 PC 실행 |

## 복사해서 쓸 양식

```text
확인 날짜 / 담당자:
코드 버전(커밋 전이면 그 사실 표시):
데이터 파일·버전 / 합성 또는 실제:
확인할 기능:
입력 또는 화면 조작 순서:
기대 결과:
실제 실행 명령 또는 확인 방법:
실제 결과:
판정: 통과 / 실패 / 미확인
남은 문제·담당자:
```

키·인증 URL·개인 연락처를 로그나 캡처에 넣지 않습니다. 실패도 남기고 수정 후 재확인 결과를 덧붙입니다. [검증 계획](../testing.md)의 항목에 대응되게 기록합니다.
