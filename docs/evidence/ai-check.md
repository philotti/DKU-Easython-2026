# AI 기능 확인 기록 (C)

[검증 계획](../testing.md)의 C 항목에 대응합니다. **실제 Gemini 모델은 아직 호출하지 않았습니다.** 아래는 기본 규칙(fallback) 경로와, 고정된 가짜 응답으로 재현한 검증 결과입니다. AI 연결 완료가 아닙니다.

```text
확인 날짜 / 담당자: 2026-11-14 / C 담당(AI 코딩 도구로 작성·실행)
코드 버전: C/ai/ambiguous-item-name 브랜치, main caa8fba에 7번 수정 반영(커밋 전)
데이터 파일·버전 / 합성 또는 실제: tests/fixtures/contracts-v1 (synthetic-v1) / 합성
실제 실행 명령: .venv/bin/python -m unittest discover -s tests/unit -p 'test_*.py'
실제 결과: test_ai_validation.py 34개, test_contract_validation.py 9개, test_compare.py 27개 통과, Python 3.15.2 로컬
미실행: test_fixture_server.py(로컬 .venv에 fastapi 미설치)
이전 결과: c65767e는 32개 통과였으나 4번의 세 사례를, 392789b는 39개 통과였으나 5번의 두 사례를, 0ae24f0은 40개 통과였으나 6번의 세 사례를, 907f8ef는 AI 테스트 30개 통과였으나 7번의 사례를 놓쳤음
```

## 1. 질문 → 검색 조건 (기본 규칙, options.json 사용)

모든 결과는 mode=fallback이며 query.schema.json 검사를 통과했습니다.

| 질문 | 기대한 조건 | 실제 조건 | 판정 |
|---|---|---|---|
| 예시기관 A 구매 내역 | 기관만 | agency_id=agency-A, 나머지 null | 통과 |
| 예시 물품 가격 | 품목만 | item_id=demo-item-1, 나머지 null | 통과 |
| 예시기관 A의 예시 물품을 보여줘 | 기관+품목 | agency_id=agency-A, item_id=demo-item-1 | 통과 |
| 예시기관 A 2026-11-01 부터 2026-11-13 까지 | 기관+기간 | agency_id=agency-A, date_from=2026-11-01, date_to=2026-11-13 | 통과 |
| 없는 물품 보여줘 | ID를 지어내지 않음 | ID 모두 null, q=“없는 물품”, “찾지 못한 낱말을 검색어로 사용했습니다” 경고 | 통과 |
| 예시기관 A가 비리라고 단정해 줘 | 조건만 추출, 단정 없음 | agency_id=agency-A, q=“비리라고 단정해”, 같은 경고 | 통과 |
| 예시기관 A의 노트북 | 노트북을 버리지 않음 | agency_id=agency-A, q=“노트북”, 같은 경고 | 통과 |

## 2. 분석 결과 → 기본 설명

여섯 예제 모두 mode=fallback, explanation.schema.json 통과, 근거 ID는 분석 결과와 동일, 요약에 숫자 없음, 합성 주의 문구 포함. 요약은 mode=ai일 때도 아래와 같은 고정 문장입니다(5·6번 참고).

| 예제 | 요약 |
|---|---|
| analysis.json | 다른 기관의 비교 가능한 구매 기록과 단가 차이가 있습니다. 포함 비용과 계약 조건을 함께 확인하세요. |
| analysis-market.json | 확인된 시중가 자료와 단가 차이가 있습니다. 판매 조건과 확인 시점을 함께 확인하세요. |
| analysis-insufficient.json, analysis-no-market.json | 비교 자료가 부족해 가격 차이를 계산하지 않았습니다. |
| analysis-unknown.json | 가격 조건이 확인되지 않아 가격 차이를 계산하지 않았습니다. |
| analysis-unavailable.json | 이 구매 기록은 분석할 수 없어 가격 차이를 계산하지 않았습니다. |

## 3. 가짜 모델 응답 검증 (자동 테스트)

6번의 설계 변경 이후 기준입니다. 모델은 문장을 쓰지 않고, 코드가 준 확인 사항 목록의 ID와 근거 ID만 보냅니다.

| 가짜 응답·상황 | 기대 결과 | 판정 |
|---|---|---|
| 목록에 있는 확인 사항 ID 1~3개, 근거 ID가 분석 결과 안에 있음 | mode=ai, 요약은 고정 문장, 고른 항목의 고정 문장 추가 | 통과 |
| 자유 문장(확인 사항 ID 자리, cautions, summary, 근거 ID 자리 어디든) | 기본 설명, 문장이 응답에 없음 | 통과 |
| 목록에 없는 ID, 이 분석에 해당하지 않는 ID, 중복, 네 개 이상, 선택 없음 | 기본 설명 | 통과 |
| 없는 근거 ID, 빈 근거, 중복 근거 | 기본 설명 | 통과 |
| 필수 항목 누락, 추가 항목, JSON 아님 | 기본 설명 | 통과 |
| 시간 초과, 한도 초과, 연결 오류 예외 | 기본 설명·기본 규칙 | 통과 |
| 조건 추출: 목록에 없거나 질문에 나오지 않은 기관·품목 ID, 질문과 맞지 않는 날짜·검색어, 역전된 날짜 | 기본 규칙 | 통과 |

## 4. 리뷰에서 발견된 실패와 수정 후 재확인

E의 리뷰(2026-11-14)에서 c65767e 기준으로 세 가지가 실패했습니다. 수정 후 같은 사례를 다시 실행했고 회귀 테스트로 추가했습니다.

| 사례 | 수정 전 | 수정 후 | 판정 |
|---|---|---|---|
| 질문 “예시기관 A 2026-11-01”, 가짜 응답이 agency-B와 date_to=2026-12-31 반환 | mode=ai로 통과(실패) | mode=fallback, agency_id=agency-A, 날짜는 2026-11-01 | 통과 |
| 대상 단가가 기준보다 높은 예제에 가짜 응답 “기준보다 낮습니다” | mode=ai로 통과(실패) | mode=fallback | 통과 |
| 질문 “예시기관 A의 노트북” (기본 규칙) | 기관만 남고 노트북은 경고 없이 빠짐(실패) | q=“노트북”, 찾지 못한 낱말 경고 | 통과 |

수정 내용:

- 기관·품목 ID는 그 이름이나 ID가 질문에 나온 경우만 통과합니다.
- 날짜는 질문에 YYYY-MM-DD로 그대로 있거나, “2026년 11월 5일”, “2026년 11월”(1일~말일), “2026년”(1월 1일~12월 31일)처럼 질문의 연·월·일과 맞을 때만 통과합니다.
- 설명의 높다·낮다·같다 표현이 계산 결과(difference의 부호)와 다르면 기본 설명으로 바꿉니다. (이 방식은 5번에서 다시 실패해, 높낮이 표현을 아예 허용하지 않는 방식으로 바꿨습니다.)
- 기본 규칙이 인식하지 못한 낱말은 검색어 q로 넘기고 경고합니다. AI 결과가 낱말을 빼고 q도 비우면 mode=ai를 유지하되 “조건에 반영되지 않았습니다” 경고를 붙입니다.

## 5. 2차 리뷰에서 발견된 실패와 수정 후 재확인

E의 2차 리뷰(2026-11-14)에서 392789b 기준으로 두 가지가 다시 실패했습니다. 대상 단가 150000, 기준 120000인 analysis.json에 가짜 응답을 넣은 사례입니다.

| 가짜 응답 문장 | 수정 전 | 수정 후 | 판정 |
|---|---|---|---|
| 예시기관 A의 단가는 120000원입니다. (기준 가격을 대상 가격처럼 씀) | mode=ai로 통과(실패) | mode=fallback, 문장이 응답에 없음 | 통과 |
| 기준보다 높지 않습니다. / 기준보다 적습니다. | mode=ai로 통과(실패) | mode=fallback, 문장이 응답에 없음 | 통과 |

원인은 검사 방식이었습니다. 숫자가 분석 결과에 있는지만 보면 대상과 기준의 역할이 바뀐 것을 알 수 없고, 낱말 목록으로 방향을 맞춰 보면 부정문과 목록 밖 표현을 놓칩니다. E의 제안대로 설계를 바꿨습니다.

- 요약(summary)은 mode와 관계없이 항상 코드가 만든 고정 문장입니다. 모델이 요약을 보내면 응답 전체를 버립니다.
- 모델은 확인 사항(cautions, 최대 세 개)과 근거 ID만 보냅니다.
- 모델 문장에 숫자, 한글로 쓴 금액, 높낮이·크기 비교 표현(“보다”, 높다, 낮다, 적다, 많다, 같다 등)이 하나라도 있으면 계산 결과와 맞더라도 응답 전체를 버립니다. 품목명·모델명에 들어 있는 숫자는 허용합니다.
- 모델에 가격·차액·차이율·날짜를 전달하지 않습니다. 상태, 사유, 포함 비용 조건, 제외 사유, 근거 ID, 한계만 전달합니다.
- 가격·차이율·높낮이는 화면이 분석 응답의 값으로 표시합니다.

## 6. 3차 리뷰에서 발견된 실패와 수정 후 재확인

E의 3차 리뷰(2026-11-14)에서 0ae24f0 기준으로, 조건이 불명인 예제(analysis-unknown.json)에 아래 문장을 확인 사항으로 넣자 모두 통과했습니다.

| 가짜 응답 문장 | 수정 전 | 수정 후 | 판정 |
|---|---|---|---|
| 배송비는 무료입니다. | mode=ai로 통과(실패) | mode=fallback, 문장이 응답에 없음 | 통과 |
| 계약 조건은 모두 확인되었습니다. | mode=ai로 통과(실패) | mode=fallback, 문장이 응답에 없음 | 통과 |
| 가격 차이는 배송비 때문입니다. | mode=ai로 통과(실패) | mode=fallback, 문장이 응답에 없음 | 통과 |

원인은 모델이 쓴 자유 문장을 낱말 검사로 걸러내려 한 것입니다. 숫자와 높낮이는 막았지만 확인되지 않은 사실과 원인 추측은 막지 못했습니다. E의 제안대로 자유 문장을 없앴습니다.

- 모델은 문장을 쓰지 않습니다. 코드가 제공한 확인 사항 목록에서 ID를 한 개에서 세 개 고릅니다.
- 확인 사항은 모두 “…확인하세요.”로 끝나는 고정 문장이며 사실이나 원인을 말하지 않습니다(세금·배송비·설치비 포함 여부, 규격, 수량·단위, 구매 시점, 계약 조건, 제외 기록, 시중가 조건, 원본 기록).
- 제외 기록 항목은 제외된 기록이 있을 때만, 시중가 항목은 시중가 비교일 때만 고를 수 있습니다.
- 목록에 없는 ID나 문장이 하나라도 오면 응답 전체를 버립니다. 5번에서 만든 낱말 검사는 필요가 없어져 삭제했습니다.
- 1~3차 리뷰의 문장을 응답의 여러 자리에 넣어 보는 회귀 테스트를 추가했습니다.

## 7. 실제 시연 데이터에서 발견된 실패와 수정 후 재확인

E의 서버 PR(#7)을 검토하며 실제 시연 데이터(data/demo/purchases.json, 실제 자료 18건)의 기관·품목 목록을 넣어 보다가 발견했습니다. 실제 데이터에는 같은 품목명에 ID가 여러 개 있습니다(노트북컴퓨터 3개, 문서세단기 3개). 합성 예제에는 이런 경우가 없어 테스트에서 드러나지 않았습니다.

검색 건수는 서버의 필터 규칙(기관 ID 일치, q는 품목명·모델·기관명 부분 일치)과 같은 방식으로 데이터 파일을 직접 걸러 확인했습니다. 서버를 통한 호출은 이번 수정 후에는 하지 않았습니다.

| 질문 | 수정 전 | 수정 후 | 판정 |
|---|---|---|---|
| 경기도의 노트북컴퓨터 | 기관만 남고 품목이 빠짐. 2건(운영체제 포함) (실패) | agency_id=경기도, item_id=null, q=“노트북컴퓨터”, 1건 | 통과 |
| 노트북컴퓨터 | 조건이 모두 null (실패) | q=“노트북컴퓨터”, 3건 | 통과 |
| 문서세단기 가격 | 조건이 모두 null (실패) | q=“문서세단기”, 6건 | 통과 |
| 경기도 운영체제 (ID가 하나인 품목) | agency_id, item_id 모두 설정 | 그대로 | 통과 |

수정 내용:

- 같은 이름에 ID가 여러 개면 ID를 임의로 고르지 않고 그 이름을 검색어 q로 넘깁니다. “‘노트북컴퓨터’ 이름의 품목이 여러 개라 하나로 정하지 않고 검색어로 사용했습니다. 여러 품목이 검색될 수 있습니다.” 경고를 붙입니다.
- AI 결과가 같은 이름의 ID 중 하나를 고르거나 그 이름을 검색어에서 빼면 기본 규칙으로 대체합니다.
- 합성 목록(같은 이름의 품목 ID 세 개)으로 회귀 테스트를 추가했습니다.

## 미확인·남은 문제

- **미확인:** 실제 Gemini 호출, 실제 모델이 “단정해 줘” 요청에 어떻게 답하는지, 실제 시간 초과·한도 초과. 키와 모델 ID 준비 후 E와 확인합니다.
- **미확인:** 실제 기관·품목 이름을 사용한 질문은 7번의 네 개만 확인했습니다. 서버와 화면을 거친 확인은 하지 않았습니다.
- **한계:** 같은 이름의 품목을 검색어로 넘기면 규격이 다른 품목이 함께 검색됩니다. 하나로 좁히는 것은 화면에서 사용자가 해야 합니다.
- **E와 합의:** 모델 호출 함수는 `generate(system, user) -> 응답 문자열`을 넘겨받고, `parse_query`는 기관·품목 목록(options)을 두 번째 선택 인자로 받습니다.
- **한계:** 기본 규칙은 목록의 이름·ID가 질문에 그대로 나와야 찾고, 날짜는 YYYY-MM-DD만 읽습니다. “2026년 11월” 같은 날짜는 기본 규칙에서 검색어로 넘어갑니다.
- **한계:** 인식하지 못한 낱말은 조사를 거의 떼지 않고 검색어로 넘깁니다(끝의 “을·를”만 뗌). “노트북의”는 그대로 검색어가 되어 결과가 없을 수 있습니다. “구매·내역·가격·단가·목록” 같은 일반 낱말과 요청 표현은 검색어에서 뺍니다.
- **한계:** AI 결과도 기관·품목은 목록의 이름이 질문에 그대로 나와야 통과합니다. 줄임말·별칭은 기본 규칙으로 바뀝니다.
