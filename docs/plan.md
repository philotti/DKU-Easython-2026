# 구현 계획 — 역할별 결과물을 연결하기

전체 서비스는 설계·구현 진행 중입니다. 합성 예제 API 서버와 React·Vite 웹 화면이 추가됐으며, 실제 데이터·비교 계산·Gemini는 아직 연결되지 않았습니다. 웹 실행은 [웹 안내](../apps/web/README.md)를 따르고 브라우저 검수는 별도로 수행합니다. 데이터 조건은 확인이 필요합니다. 일정표 대신 아래 결과물을 기준으로 진행합니다.

## 1. 먼저 완성할 한 흐름

사용자 요청에 따라 도청 목록 → 분석 순위 → 도청별 상세 근거 흐름으로 변경합니다. D는 화면 뼈대를 만들고 비교 기준·이상치 판정·점수 집계는 담당 팀원이 제공합니다. 기준과 근거를 받기 전에는 순위·점수를 생성하지 않습니다. [화면 명세](screen-spec.md)를 따릅니다. 기존 구매 예제 API는 도청 순위 API가 아니므로 현재 화면에는 연결하지 않습니다.

## 2. 만들 모듈과 책임

| 담당 | 제안 파일 | 입력 → 출력 |
|---|---|---|
| A | `data/demo/purchases.json`, `market-prices.json` | 공식 자료 → 검수된 내부 데이터 |
| B | `analysis/compare.py` | 대상 ID·구매·시중가·비교 유형 → 분석 결과 |
| C | `ai/query.py`, `ai/explain.py`, `ai/prompts.py` | 질문 → 조건 / 분석 결과 → 설명 |
| D | `apps/web/src/`의 카드·막대·패널 컴포넌트 | 서버 응답 → 화면 |
| E | `api/server.py`, `search/repository.py` | 웹 요청 → 조회·계산·설명 연결 |

짧게 쓴 Python 경로는 `src/budget_transparency/` 아래입니다. 파일명은 역할 문서와 맞춘 제안이며, 변경할 때 E가 관련 문서·예제를 함께 갱신합니다. D의 React 파일 경로는 해당 스택 채택 시 사용합니다.

## 3. 데이터가 흐르는 방법

A가 출처를 확인한 JSON을 E에게 전달합니다. E가 로딩·검색하고 B의 `compare_purchase(record_id, purchases, market_prices, comparison_type)`를 호출합니다. D는 계산 결과로 카드와 상세를 그립니다. C의 `explain_analysis(analysis)`는 같은 근거를 받아 설명합니다. 설명 요청은 수치 조회와 분리합니다.

자연어 검색은 C의 `parse_query(text)` → E의 허용 필드 검증·저장 데이터 검색 순서입니다. C는 문장 해석을, E는 실제 목록 조회·필터·정렬을 책임집니다. AI가 SQL이나 임의 URL을 실행하지 않습니다.

## 4. 비교 기준을 정하는 순서

1. A·B가 제품 식별자·규격·단위·날짜·금액 의미를 확인합니다.
2. B가 비교 대상에서 대상 기관·중복·취소·다른 규격을 제외합니다.
3. 비교 기간·최소 건수와 기관 수·수량 조건·포함 비용을 A·B·E가 정해 [결정 기록](decisions.md)에 남깁니다.
4. 기관 간 기준은 비교 가능한 다른 기관의 구매 건별 중앙값을 시작안으로 합니다. 반복 구매가 많은 기관의 영향도 검토합니다.
5. 차액 = 대상 단가 - 기준 단가, 차이율 = 차액 / 기준 단가 × 100. 기준이 없거나 0이면 계산하지 않습니다.
6. 시중가는 별도 자료에서 선택하며 복수 가격의 채택 규칙도 기록합니다.

조건이나 정책이 확정되지 않으면 비교 가능으로 판정하지 않습니다. 총계약금액을 혼합 품목 수량으로 나누지 않습니다. 도청별 순위는 새 목표에 포함하며 이상치 판정·점수 집계는 담당 팀원의 후속 작업입니다. D는 전달받은 결과를 표시하고 자체 임계값을 만들지 않습니다.

## 5. 기술과 환경

사용자 요청으로 웹은 React/JavaScript와 Vite를 설치해 채택했습니다. TypeScript는 미적용이며 서버는 기존 Python/FastAPI를 사용합니다. 설치·실행 방법은 웹 안내를 따릅니다. 저장은 초기 JSON, AI는 Gemini API를 사용하려는 방향입니다. 정확한 모델 ID·한도·호출 성공은 C·E가 확인합니다. 로컬 모델 학습과 GPU 설치는 하지 않습니다.

`.env.example`은 키 없는 공유 양식, `.env`는 각자 로컬 설정입니다. 서버에서만 키를 읽습니다. 파일 다운로드 방식에는 공공 API 키가 필요하지 않습니다.

## 6. 실패해도 유지할 동작

| 문제 | 처리 | 담당 |
|---|---|---|
| 실제 데이터 미확보 | 합성 표시 예제로 개발, 실제 검증 미완료 공개 | A·E |
| 비교 조건 불명·표본 부족 | 수치 null과 사유, 원본 열람 유지 | B·D |
| 시중가 없음 | 시중가 없음 표시, 기관 가격으로 대체하지 않음 | B·D |
| AI 오류·없는 근거 출력 | 기본 설명, 계산·출처는 유지 | C·E·D |
| 서버 오류 | 재시도 안내, 정상 결과처럼 표시하지 않음 | E·D |
